## 独立配置

- 用户根：`miniapp`，保留原 `wxe87cc0779829a077`，十三页、原首页/订单/我的三 tabs，无设备定位声明或调用。

## 离线命令

从项目根运行，无需 npm install。

```sh
node scripts/sync-miniapp-shared.cjs --check
node scripts/check-miniapps.cjs
npm run check:wechat --prefix miniapp
npm run check:wechat --prefix rider-miniapp
npm run check:release --prefix miniapp
npm run check:release --prefix rider-miniapp
```

静态检查和 wx-mock 不是官方编译、真机验收或后端部署证明。官方 WXML/WXSS 编译器可用时仅在临时输出目录执行，不生成业务 dist，不上传。编译器缺失应明确报告未执行，不能用假产物代替。

## 真机与隔离环境验收

- USER→RIDER、RIDER→USER 两个方向均覆盖：已绑定直接登录；未绑定明确关联/创建选择；另一端当前账号新 wx.login + 确认签发43字符一次性码；目标端确认；过期、重放、错误目标、冲突、拒绝手机号、隐私未同意、网络丢回包重新登录恢复。不跨端传 token/手机号/草稿。
- 入驻：未认证先登录；非 RIDER 不可操作工作台；当前账号姓名/16字以内车牌、本次真实手机号授权，之前已绑号不能替代；角色变化后重新登录；已有 RIDER 读取档案直接回工作台。接送与代驾默认关闭且分别由后端授权，平台授权不等于驾驶资质。
- 原配送和服务工作流完整保留，真实位置仅配送主动点击上报，无后台定位；ONLINE/ONSITE/PART_TIME/RIDE/DRIVING 无取件码与位置上报。
- 转派 incoming/outgoing 独立分页、上线后接受、拒绝/撤销、履约自动过期、未知结果先查；原骑手交接后仍可看转派记录，但履约和私有详情读取被后端拒绝。
- 骑手详情仅严格 carrier GET；不存在消费者发布、支付、取消、确认、评价、投诉申请或轨迹按钮/API。用户侧原飞毛腿/BUY/接送/代驾/自定义发布、地址旧 poiName 兼容与已删除地点名称输入、订单投诉、钱包等逐项回归。
- 凭证轮换/40101：匿名页无原金额或地址，同 userId 重登恢复准确原 orderId 和提现 requestId，不重复创建；不同账号不继承；显式退出和换服务完整清除。普通403保留会话；旧token晚到401不能清新会话；旧页面/上传/网络回调均隔离。
- 钱包未知结果原编号原金额重试，服务端冻结一次；不本地构造金额。两端资料和手机号更换不变更userId、订单、钱包、草稿或角色。
