# 微信原生小程序迁移说明

## 范围与导入

- 新源码在 `miniapp/native`，由手写 `App` / `Page`（公共 `definePage` 最终调用原生 `Page`）及 `wx` API 实现。不依赖 uni-app、Vue、Vite 或旧 `dist` 编译产物。
- 保留 `miniapp/src`、旧依赖和历史编译目录。仅给旧 `src/api/request.js` 补上 API 已在使用的 `get/post/put/delete` 兼容方法，修复 `request.post` 不存在。原生入口不会加载旧源码。
- 微信开发者工具直接导入 **miniapp 目录**，`project.config.json` 的 `miniprogramRoot` 已设为 `native/`。
- 微信 AppID **只在 `miniapp/project.config.json` 配置**，默认 `touristappid`，不编造真实 AppID。联调时换成运营方真实 AppID，并让后端使用同一 AppID 及配套 Secret；Secret 不得写进前端。不要在 `native/config.js` 或旧 manifest 再配置微信 AppID。
- 默认 API 根地址为 `http://localhost:8080`，定义于 `native/config.js` 的 `BASE_URL`。也可从“我的 → 服务连接设置”保存本机覆盖配置。切换服务会清除登录态和草稿，避免凭证发往其他服务。
- 真机的 localhost 是手机自身，需改为可达的电脑局域网地址。开发 HTTP 联调可在开发者工具**本地设置**临时关闭域名校验；项目未默认关闭检查。生产使用 HTTPS 和正式 request 合法域名。
- 无需 `npm install` 或编译即可导入原生源码。现有 npm 依赖仅为保留旧工程；原生校验、测试只使用 Node 内置模块。

## 接口契约

保留 `/api/v1` 下已有接口路径及请求字段。新增微信登录调用为：

```text
wx.login → POST /api/v1/auth/wechat-login
{ "code": "微信临时code", "agreed": true }

Result<LoginVO>
data: { token, userId, role: "USER", nickname }
```

- 客户端不传 openid、不伪造手机号，不调用 `getPhoneNumber`。微信登录无需手机号；配送联系人电话在业务表单手工填写。
- 协作后端已告知实现此接口、微信身份映射及无手机号 `/user/me` 兼容；本端以实际接口响应为准，未进行真实微信平台换码验证。
- 手机号绑定暂未实现，微信账号与短信账号**不自动合并**。骑手入驻仍为现有短信/手机号流程，成功后使用接口返回的 RIDER 账户，不宣称与微信用户订单合并。
- 用户订单 `OrderVO` 使用 **`status`**（如 `WAIT_PAY`、`DELIVERED`、`FINISHED`），不是 `statusCode`。只有骑手专用 `/rider/orders` 保留其现有 `status` 中文标签及 `statusCode` 状态码返回结构。
- 默认地址沿用 `PUT /user/address/{id}`、`isDefault: 1`，不发明默认地址端点。
- 金额为分，JS 中转换为元；WXML 不调用格式化函数，不内嵌对象或函数。
- 轨迹查询返回倒序点，前端反转；坐标使用 `wx.getLocation({type:'gcj02'})`。设备未提供有效速度时传 `null`，不模拟速度。定位拒绝/失败不调用上报接口。

## 请求、安全与生命周期

- Promise 封装 `wx.request`，统一 Bearer Token、超时、HTTP 非2xx、业务非0、格式错误与网络错误；401清理登录态并导向登录。切换账户后旧请求响应不再进入页面。
- 页面级提交锁和按钮禁用避免重复点击；输入长度及必填/手机号/数值检查。旧请求层只补兼容方法，原生完整错误处理在 `native/utils/request.js`。
- 创建订单前记录“结果待核实”，拿到 ID 后立即持久化。支付失败重试同一 ID；创建超时、5xx或响应缺少 ID 时阻止盲目重复提交，提示先去订单列表核实。**后端未提供创建幂等键，不能承诺网络故障下服务端绝对不重复建单。**
- 公共 Page 生命周期在隐藏/卸载时清定时器，卸载后不再 setData；轨迹不后台轮询。短信冷却按绝对时间恢复，不依赖残留 interval。
- 骑手取件码必须手填非空并确认，不再提交空串。定位在点击上报并确认后才获取；获取中隐藏页面/切换账户则不发送该位置。没有后台持续定位承诺。
- 已评价标记仅为本机便利提示，一单一评、评价期限以服务端为准；没有臆造“已评价查询”接口。

## 明确未接入的能力

- **MOCK 支付**：只调用现有 `/orders/{id}/pay` 模拟接口，不调用 `wx.requestPayment`，不发生真实扣款/退款。相关页面、按钮、确认框均明确标记。
- 无照片上传、OCR或送达照片凭证接口；不把旧 uni 页面本地选图数量当成上传成功。当前原生不展示伪上传入口，骑手送达会说明仅推进演示状态。
- 无微信手机号绑定/短信账号合并、地图路线自动测距、后台定位、真实实名认证/培训审核或账号注销接口。
- 地址簿经纬度沿用已有资料；纯手填地址不伪造坐标，轨迹不随机生成。

## 可重复校验

Node 18+，在 miniapp 目录运行：

```bash
npm run check
npm test
npm run build
# Windows 上装有微信开发者工具时，使用官方编译器校验模板/样式：
npm run check:wechat
```

`check:wechat` 自动查找默认安装目录；非默认安装可设置 `WECHAT_DEVTOOLS_HOME`。此命令只做本机编译，不上传或发布小程序。

也可不经 npm，直接运行：

```bash
node miniapp/scripts/check-native.cjs
node miniapp/scripts/test-native.cjs
```

`build` 为原生检查与测试，不生成编译产物。原生开发直接使用微信开发者工具。旧命令仅保留为 `legacy:dev:mp-weixin`、`legacy:build:mp-weixin`，其输出不是本次原生入口。

静态脚本会检查：miniapp 源码及脚本 JS/CJS 语法、JSON 合法性（排除 node_modules/dist）、app.json 全部页面四件套、tab 路径、require/跳转路径、事件处理函数、WXML 标签和简单表达式、原生区无 uni/Vue/Vite 运行时引用、AppID 单一配置与无随机轨迹。旧 `.vue` 为保留历史文件，不由 Node 当作 JS 解析。

wx mock 行为测试覆盖：请求成功/HTTP/业务/格式/网络错误、401、旧账户响应丢弃、同意与微信 code 契约、用户 status、地址选择与默认更新、空取件码拒绝及真实码传递、真实定位/拒绝授权、隐藏卸载计时器清理、冷却与提交锁、支付失败复用订单、未知创建结果阻止重提、订单分页与报价失效。

本次 `npm run build` 已通过：**21个JSON、27个JS/CJS、13套页面与13个WXML；17/17项 wx mock 行为测试**（包括微信老用户保留 RIDER 身份及拒绝管理员响应）。另已用本机微信开发者工具内置的 `wcc.exe` 和 `wcsc.exe` 分别编译全部 WXML/WXSS，均返回退出码0。

## 仍需开发工具/真机验收

已通过微信官方 WXML/WXSS 命令行编译，但尚未完成模拟器界面和真机验收；不能将静态和 mock 测试视为真实微信授权或完整前后端联调。请按以下顺序实测：

1. 导入 miniapp，确认走 native 页面；配置可信服务及真实 AppID，并与后端匹配。
2. 使用真实 AppID/Secret 验证 `wx.login` 换码、USER 身份、无手机号资料展示；验证短信备用及明确的演示码。
3. 地址增删改默认及从下单页选择；修改计价字段后必须重新报价。
4. 创建、MOCK 支付、失败重试、列表分页、取件码、取消、确认、评价、投诉。
5. 短信骑手入驻、上线抢单、错误/正确取件码、出发与真实定位权限允许/拒绝、送达。
6. 用户轨迹地图、实际点位坐标系、权限范围、断网恢复和前后台切换。地图渲染、定位能力及高精度可用性依赖开发者工具/真机与微信后台资质。
7. 上线前补全运营方服务/隐私正式文本、用户隐私保护指引、定位能力申请及合法域名；真实交易上线前必须另接入合规支付、退款及相关凭证能力。
